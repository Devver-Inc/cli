Opt-in public deployment URLs over OpenTunnel. `devver publish [deployment-id]` shares a ready local deployment at an HTTPS URL, defaulting to the latest deployment on the attached server (and failing if that deployment is not ready), `devver publish --open` opens the published URL in a browser, `devver unpublish <deployment-id>` removes it, and `devver deploy --public` publishes after local readiness. The server runs a per-instance OpenTunnel connector and a loopback app-only ingress that forwards HTTP and WebSocket/HMR to the deployment while rejecting any hostname but the one assigned to it; the control API never crosses the tunnel. Published routes reconnect after a server restart. New routes admit traffic only after publication is saved; unpublishing revokes active HTTP streams and WebSockets locally even when relay cleanup fails. Changes to route names reattach the shared tunnel, so other WebSockets may need to reconnect. Anyone with the URL can reach the app, which `publish` states before sharing. In the local TUI, `s` publishes the selected ready deployment after confirmation; `o` opens and `c` copies its public URL, and the detail panel shows both local and public URLs. Source builds require Bun >=1.4.0 to avoid stalled tunnel TLS handshakes, and standalone builds reject older compilers.
