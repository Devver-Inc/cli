# Local Git source sharing and `--watch`: research and recommendation

## Scope and current contract

This is research, **not** a change to the local-server decision map or an implementation plan. The current server API exposes identity only; the existing CLI `deploy` pushes a named branch to the cloud and creates a cloud deployment (`packages/server/src/api.ts`, `packages/cli/src/cli/deploy.ts`, `packages/cli/src/util/git/index.ts`). The local committed-deploy design instead calls for a registered checkout mirrored to a **local bare repo**, an explicit deploy selecting exact committed `HEAD`, detached revision worktrees and retained rollback history. Mirroring is background preparation, never implicit deployment; missed notifications must be repaired on deploy/restart ([#65](https://github.com/Devver-Inc/cli/issues/65), [#68 resolution](https://github.com/Devver-Inc/cli/issues/68#issuecomment-5992845577), [#73 resolution](https://github.com/Devver-Inc/cli/issues/73#issuecomment-6019405985)). `--watch` is a **later** ephemeral, isolated workspace and process with loopback HTTP preview only; no durable tree node, amend, rollback, public preview, overlay or comments. Its Node development command provides framework-specific HMR; static content needs live reload. Stop/disconnect grace must clean up ([#74 resolution and superseding comments](https://github.com/Devver-Inc/cli/issues/74), [#65 final scope](https://github.com/Devver-Inc/cli/issues/65#issuecomment-6023841817)).

## What a Git “stream” can and cannot replace

| Mechanism | What it supplies | Limit for Devver |
| --- | --- | --- |
| Git hooks | `post-commit` observes `git commit`; `post-checkout`, `post-merge`, `post-rewrite`, `post-index-change`, and `reference-transaction` cover their documented operations/stages. `post-receive` runs **on the receiving repository**, after a receive operation; it is not a subscription to every local file edit ([githooks](https://git-scm.com/docs/githooks)). | There is no documented universal Git worktree-change event. Hooks require installation and can be changed through `core.hooksPath`; an editor's unstaged write/untracked file is not a Git operation. Treat hooks as optional wakeups and periodically reconcile refs and source state. Do not alter a developer's existing hooks without consent ([githooks](https://git-scm.com/docs/githooks), [git-config](https://git-scm.com/docs/git-config), [#73](https://github.com/Devver-Inc/cli/issues/73#issuecomment-6019405985)). |
| File watching | OS-backed `fs.watch` observes paths, but Node warns it is not fully consistent across platforms, network filesystems, virtualization, and missing filename notifications; replacement can change the watched inode ([Node fs.watch](https://nodejs.org/api/fs.html#fswatchfilename-options-listener)). | Use as a dirty signal, not an authoritative ordered diff log; debounce and fully rescan, including after overflow/error, reconnect, checkout/rename, and at startup. Never infer a deletion solely from a missing watcher callback ([Node fs.watch](https://nodejs.org/api/fs.html#fswatchfilename-options-listener), [git-status](https://git-scm.com/docs/git-status)). |
| Git object transfer | `git fetch` transfers refs and the **objects necessary** for the selected history; a diff or changed-ref notification by itself does not make a commit/tree/blob available in another repository ([git-fetch](https://git-scm.com/docs/git-fetch), [git-push](https://git-scm.com/docs/git-push)). | For an independent bare store, verify/sync the exact SHA and keep it reachable with Devver-owned retention refs before checkout; avoid blind ref pruning/force-update removing needed history ([git-fetch](https://git-scm.com/docs/git-fetch), [git-gc](https://git-scm.com/docs/git-gc), [#68](https://github.com/Devver-Inc/cli/issues/68#issuecomment-5992845577)). |
| Linked worktrees | `git worktree add --detach <path> <commit>` shares a repository's objects/refs but gives each worktree its own `HEAD` and index; a bare repo can be the main repository. Git tracks linked-worktree administrative metadata and documents `remove`, `prune`, `repair` and `lock` ([git-worktree](https://git-scm.com/docs/git-worktree)). | This can avoid a _second object store_ on the same host, **not** extra checked-out files or install/build outputs. A deployment that borrows the developer repo's Git directory shares its lifecycle and Git metadata, including refs and maintenance; isolate and retain refs explicitly ([git-worktree](https://git-scm.com/docs/git-worktree), [git-gc](https://git-scm.com/docs/git-gc), [#71](https://github.com/Devver-Inc/cli/issues/71#issuecomment-6018744149)). |

A ref event can give an old/new object ID, not a guaranteed materialized snapshot of modified, staged, deleted and untracked bytes. `git status` distinguishes index/worktree changes, deletions, untracked and ignored paths; `.gitignore` applies to **untracked** paths, not tracked ones. `git ls-files --cached` lists tracked index entries, while `--others --exclude-standard` lists untracked non-ignored paths ([githooks](https://git-scm.com/docs/githooks), [git-status](https://git-scm.com/docs/git-status), [gitignore](https://git-scm.com/docs/gitignore), [git-ls-files](https://git-scm.com/docs/git-ls-files)).

## Alternatives and recommendation

1. **Direct detached worktrees of the registered developer repository:** `git -C <registered-repo> worktree add --detach <server-owned-path> <verified-SHA>` avoids a second Git object store and network/pack transfer, while keeping checkout/index per deployment ([git-worktree](https://git-scm.com/docs/git-worktree)). For the same-user, same-machine, explicitly registered checkout this is technically viable; it is **not** a Git stream. Tradeoff: source repo deletion/move, permissions or concurrent maintenance can break linked worktrees; repair/lock mechanisms exist but are not independent ownership. A server running untrusted app scripts without sandboxing must not rely on a path boundary to protect the developer repo: deployment has the same host account privileges ([git-worktree](https://git-scm.com/docs/git-worktree), [#70](https://github.com/Devver-Inc/cli/issues/70), [#71](https://github.com/Devver-Inc/cli/issues/71#issuecomment-6018744149)). A pinned SHA must stay reachable through owned refs, rather than assuming branch heads/reflogs persist after rewrite and GC ([git-gc](https://git-scm.com/docs/git-gc), [git-update-ref](https://git-scm.com/docs/git-update-ref), [#68](https://github.com/Devver-Inc/cli/issues/68#issuecomment-5992845577)).
2. **Current independent local bare store + detached worktrees:** sync committed refs/objects in background; at explicit deploy fetch/check the selected SHA, pin retention ref, then create a detached worktree; replace an amend only after readiness. This costs a second Git repository/object store (local clone may hardlink objects on supported local paths, but independent ownership must not depend on this optimization), while enabling Devver-owned retention and lifecycle ([git-clone](https://git-scm.com/docs/git-clone), [git-fetch](https://git-scm.com/docs/git-fetch), [git-worktree](https://git-scm.com/docs/git-worktree), [#68](https://github.com/Devver-Inc/cli/issues/68#issuecomment-5992845577), [#71](https://github.com/Devver-Inc/cli/issues/71#issuecomment-6018744149)). **Recommend this for the first committed-deploy slice**: it honors the decided ownership boundary; use notifications only to reduce sync latency, not for correctness ([#73](https://github.com/Devver-Inc/cli/issues/73#issuecomment-6019405985)). A switch to direct worktrees should be an explicit revision of #73 after measuring real disk/latency, not an incidental optimization.
3. **Object alternates / `clone --shared`:** separate ref namespace while borrowing developer objects, but Git explicitly warns that deleting source branches and source garbage collection can render borrowed objects unusable. `--dissociate` copies required objects and loses that space-saving property. Not a durable rollback source without a deliberate object-lifetime protocol ([git-clone](https://git-scm.com/docs/git-clone)).
4. **Diff-only feed / synthetic commits:** a patch is not necessarily a complete object graph and excludes untracked files unless independently collected; staging files or creating commits inside the developer repository would mutate developer Git state and incorrectly assign preview identity. Prefer file snapshot transport into temporary workspace for watch; if a later remote mode needs transfer, send a manifest plus bounded bytes over an authenticated transport, not assume shared paths ([git-diff](https://git-scm.com/docs/git-diff), [git-status](https://git-scm.com/docs/git-status), [git-fetch](https://git-scm.com/docs/git-fetch), [#74](https://github.com/Devver-Inc/cli/issues/74)).

## Smallest viable later `--watch` design (proposal, not implemented)

- **Start/ownership:** Require an explicit registered local checkout and selected server, create a random session ID and server-owned temporary directory, route and process; keep previews separate from committed deployments and do not push, commit, amend or mutate developer index/worktree. Default loopback URL only. The current server is loopback/unsandboxed; a browser-accessible control path still needs its existing Host/Origin checks and strict session/path validation ([#65](https://github.com/Devver-Inc/cli/issues/65), [#68](https://github.com/Devver-Inc/cli/issues/68#issuecomment-5992845577), [#74](https://github.com/Devver-Inc/cli/issues/74#issuecomment-6023828826), [#70](https://github.com/Devver-Inc/cli/issues/70)).
- **Initial authoritative scan:** Take tracked _worktree_ contents (not just index blobs; staged and unstaged edits both count), omit tracked deletions, add non-ignored untracked files using Git's own ignore handling (`git ls-files -z --cached` and `git ls-files -z --others --exclude-standard`, reconcile against disk; or parsed `git status --porcelain=v2 -z`). NUL framing handles arbitrary Git pathnames; do not parse human status text. Explicitly exclude `.git` (including linked-worktree gitfiles), Devver private state and dependency/build directories even if tracked; document the exclusion policy and test conflicts with tracked files. A `.gitignore` exception may reinclude a child only if its parent directory is not excluded ([git-ls-files](https://git-scm.com/docs/git-ls-files), [git-status](https://git-scm.com/docs/git-status), [gitignore](https://git-scm.com/docs/gitignore), [git-worktree](https://git-scm.com/docs/git-worktree), [#74](https://github.com/Devver-Inc/cli/issues/74#issuecomment-6019566227)).
- **Safe mirror:** Treat source paths as untrusted. Reject traversal/absolute entries and symlinks that resolve outside the checkout; do not traverse symlink directories. Validate destination containment and symlinks independently; copy regular eligible files to a fresh staging tree, compare/cancel/rescan if files changed during copy, then reconcile a manifest (including deletions and renames as remove+add) into the preview tree. Bound file size, file count, total bytes and concurrent copies; protect private state with owner-only access. These are proposed safeguards, not a claim that Git ignores or filesystem events ensure isolation. Local unsandboxed app code can still read host resources under the server account ([#74](https://github.com/Devver-Inc/cli/issues/74#issuecomment-6019566227), [#70](https://github.com/Devver-Inc/cli/issues/70), [Node fs.watch](https://nodejs.org/api/fs.html#fswatchfilename-options-listener)).
- **Updates:** Watch both source tree and ignore/config inputs; coalesce rapid signals into one per-session serial rescan, retain a dirty bit for changes arriving mid-scan, and periodically reconcile even if no event fires. Compare hashes/metadata as appropriate and send actual bytes, not a Git patch or just a changed-path list; retry when reads race atomic editor replacements. Fail visibly rather than publish partial private paths. Do not promise a single atomic revision for each keystroke; broken code stays a preview error, retry on correction. Commit/ref changes notify background mirror but **never** implicitly deploy ([Node fs.watch](https://nodejs.org/api/fs.html#fswatchfilename-options-listener), [#74](https://github.com/Devver-Inc/cli/issues/74#issuecomment-6019566227), [#73](https://github.com/Devver-Inc/cli/issues/73#issuecomment-6019405985)).
- **Process/lifecycle:** Run an explicit dev command for Node; proxy its HTTP/WebSocket HMR route and offer static reload on completed copy, not generic framework HMR. Lockfile/manifest changes trigger the necessary installer in preview workspace only, under approval policy. On stop remove route/process/workspace; on disconnect allow a bounded reconnect lease, expire it, and reconcile orphan sessions on server restart. Never clean a committed deployment's worktree because a preview ends; implement cleanup in error/cancellation paths too ([#74](https://github.com/Devver-Inc/cli/issues/74#issuecomment-6019566227), [#71](https://github.com/Devver-Inc/cli/issues/71#issuecomment-6018744149), [#73](https://github.com/Devver-Inc/cli/issues/73#issuecomment-6019405985)).

## Open decisions and proof points

- Measure second-store object bytes versus checked-out files/dependencies/build outputs and warming latency on representative projects; benchmark direct worktree versus independent bare store before reopening #73 ([git-worktree](https://git-scm.com/docs/git-worktree), [git-clone](https://git-scm.com/docs/git-clone), [#73](https://github.com/Devver-Inc/cli/issues/73#issuecomment-6019405985)).
- Decide explicit retention-ref namespace, registration/unregistration ownership, ref reconciliation interval, SHA fetch authorization, maintenance concurrency and exact GC/prune policy before implementation; test force-push, branch deletion, selected SHA no longer at any branch, failed fetch, restart, repo relocation/deletion and multiple deployments pinned to one commit ([git-fetch](https://git-scm.com/docs/git-fetch), [git-gc](https://git-scm.com/docs/git-gc), [git-worktree](https://git-scm.com/docs/git-worktree), [#68](https://github.com/Devver-Inc/cli/issues/68#issuecomment-5992845577)).
- Watch test matrix: staged-only, unstaged, untracked, ignored, ignored-parent exception, deletions/renames, symlinks and symlink swaps, submodules, nested repositories, large/binary files, file replacement during copy, ignored-rule changes, burst edits/overflow/missed notifications, rapid branch checkout, concurrent preview sessions, lockfile reinstall failure, HMR WebSocket, restart and reconnect grace, cancellation/cleanup on macOS/Linux/Windows. Verify preview bytes and exclusions by actual served HTTP, not merely watcher callbacks ([git-status](https://git-scm.com/docs/git-status), [gitignore](https://git-scm.com/docs/gitignore), [Node fs.watch](https://nodejs.org/api/fs.html#fswatchfilename-options-listener), [#74](https://github.com/Devver-Inc/cli/issues/74)).
- Remote attach/uncommitted sync, public preview, and a trust boundary against same-user malicious application processes are **not solved** by this proposal; they remain deferred or unsandboxed under the recorded first-release scope ([#65](https://github.com/Devver-Inc/cli/issues/65), [#70](https://github.com/Devver-Inc/cli/issues/70), [#74](https://github.com/Devver-Inc/cli/issues/74#issuecomment-6023828826)).
